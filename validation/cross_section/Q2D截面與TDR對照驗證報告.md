# Q2D 截面阻抗與 TDR 的首次對照

此工具由虎門科技資深技術工程師 Jeff Hong 洪敬傑提供

日期：2026-08-16　對應 ADR-0051、ADR-0052、ADR-0053

---

## 一、這份驗證回答什麼

截面阻抗功能剛接上 Q2D 求解核心，需要一個「它算出來的數字有沒有意義」的答案。工具本身的單元測試只能證明程式沒有壞掉，證明不了物理。

因此拿**同一條實體走線**，用兩個沒有共用假設的方法各算一次：

| | 方法 | 產出 |
| --- | --- | --- |
| Q2D | 從 EDB 逐層重建二維截面，Maxwell 2D Extractor 求 RLGC | 選定座標的精確 Z₀ |
| TDR | SIwave 2.5D 混合求解的 S 參數 → 步階響應 → Z(距離) | 沿線的阻抗剖面 |

兩者唯一的共通點是那條走線本身。Q2D 不知道 S 參數存在，TDR 不知道疊構長什麼樣。

**單一個 Q2D 數字和一條 TDR 曲線不可比較**，所以取六個位置組成 Z₀(x) 再對照。

## 三、切線放在哪裡，為什麼

走線路徑串出來之後，弧長與座標的對應顯示有兩段純水平的直線段：弧長 70～100 mm（y 固定 82.804 mm）與 130～170 mm（y 固定 80.137 mm）。這兩段的走線與 X 軸平行，取 X 向切線的夾角是 0°，虛胖倍率 1.000。

切線因此放在這兩段內，各三條。**這是刻意的**：ADR-0051 規定夾角超過 20° 拒絕放置，而轉角處本來就違反「結構沿線均勻」的前提。挑直線段不是為了讓數字好看，是因為斜切的數字沒有意義。

工作範圍取訊號兩側各 7 mm，遠大於建議的「導體到參考面高度的 10 倍」。

## 四、結果

TDR 側的 Z 取該 x 座標 ±1 個空間解析度（±0.502 mm）內所有取樣點的中位數。

| x (mm) | Q2D Z₀ (Ω) | TDR Z₀ (Ω) | 差 (Ω) | 差 (%) | 求解 (s) |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 85.0 | 48.602 | 48.435 | +0.167 | +0.35 | 51.0 |
| 95.0 | 48.608 | 48.516 | +0.092 | +0.19 | 17.6 |
| 105.0 | 48.654 | 48.615 | +0.039 | +0.08 | 19.8 |
| 145.0 | 48.644 | 48.889 | −0.245 | −0.50 | 19.9 |
| **155.0** | **47.632** | 48.945 | **−1.314** | **−2.68** | 22.0 |
| 165.0 | 48.627 | 49.011 | −0.385 | −0.78 | 17.6 |

| | 中位數 | 範圍 |
| --- | ---: | --- |
| Q2D（6 個截面） | **48.617 Ω** | 47.632 – 48.654 |
| SIwave → TDR（通道內部，弧長 20～170 mm） | **48.625 Ω** | 48.036 – 49.105 |
| **中位差** | **−0.0071 Ω（−0.015%）** | |

六條裡五條落在 ±0.4 Ω（±0.8%）內。第一條的 51 秒含 AEDT 啟動，其餘五條共用同一個工作階段，各約 18～22 秒。

另有一條獨立跑的 x = 100 mm 截面（不在上表內）：Z₀ = 48.635 Ω，Zodd 48.448、Zeven 48.823、Zdiff 96.896 Ω。ST_CTL 與 ST_ERROR 的單端 Z₀ 分別是 48.635 與 48.636 Ω——兩條線在該截面上幾何完全相同，算出來就該一樣，差 0.001 Ω 是座標平移沒出錯的自洽證據。

## 五、唯一的分歧：x = 155 mm

Q2D 在這裡低了 1.31 Ω（2.68%），而兩側 10 mm 的鄰居都正常。**這不是數值假象，那個位置的截面真的不一樣。**

四顆 GND 縫合 Via 距切線中心只有 **0.060 mm**，而焊墊半徑 0.533～1.143 mm——切線直接穿過它們。截面因此出現三個結構差異：

| | x = 157（正常） | x = 155 |
| --- | --- | --- |
| L2 參考面 | 一整片 12100 µm | 碎成 9 段（334／622／478／622／2580／290／480／290／5088 µm） |
| L3（訊號層） | 只有兩條訊號 | 多出兩段 GND 銅箔：1722 µm 與 1060 µm |
| 其他層 | 無 | BASE／L7／L6／L5／L4／SURFACE 每一層都出現 Via 柱體 |

關鍵是 L3 上那段 1060 µm 的 GND：它與 ST_CTL 的邊緣只差 **0.512 mm**，是同一層、接地、緊鄰訊號的銅箔，會直接加上對地電容。

**走線本身沒有變**：ST_CTL 在 145／155／157／160／165 全都是 202 µm、ST_ERROR 全都是 204 µm，位置也相同。所以這不是線寬效應，是周邊環境。

TDR 在同一位置讀到 48.945 Ω，比鄰居還略高，完全沒有反映這個下陷。這正是 Q2D 相對時域方法的價值：它給的是選定截面的精確阻抗，包含遠小於時域解析度的細節；代價是只在切的那個座標成立。

**有一件事這份驗證沒有做**：L2 參考面碎裂（回流路徑減少，阻抗往上）與 L3 同層接地銅（電容增加，阻抗往下）方向相反，實測淨效果是往下 1.31 Ω，但哪一項主導**沒有分開驗證**。要確認得各自建一個模型比對。目前能確定的是截面結構真的不同。

## 六、順帶驗證到的兩件事

**ADR-0051 的 Via 規則在真板上行為正確。** x = 155 的四顆是 GND 縫合 Via，工具沒有擋（照設計併入參考導體），但標了四個 `risk`（反焊盤，距 0.06 mm）。規劃時特意把「禁掉所有 Net 的 Via」排除掉，理由是有縫合 Via 的板子會完全切不下去——這條切線正好證明那個判斷：真的擋掉的話，這個有意義的局部阻抗變化就永遠看不到了。

**兩個 AEDT 工作階段並存不會造成卡死。** 全程與另一個專案的 AEDT（PyAEDT 0.23.0，固定 gRPC 埠 50051）並行，本工具用 PyAEDT 1.2.0、動態配埠（實測拿到 53429、56657），六條連續求解正常完成並釋放。

這次測試同時排除了一個先前的假設：2026-08-16 凌晨後端被拖死的那次事故，起因是 **AEDT 自己在 Circuit 建立途中崩潰**，連線斷掉後 PyAEDT 的重建嘗試走回同一條壞路徑才遞迴到堆疊耗盡。併發本身不是原因，只會提高崩潰機率。

## 七、這份驗證不能拿來當什麼

- **不是這片板子的阻抗簽核。** 這是示範板，六個截面全部挑在直線段上，涵蓋不到轉角、Via 過渡與元件端 launch。
- **不是 Q2D 或 TDR 的絕對精度證明。** 兩者一致只代表它們沒有共用的系統性錯誤，不代表兩者都對。要談絕對值得有實測或第三個方法。
- **TDR 側是單端反射（S11）推得**，不是差動 TDR。
- **求解檔位固定 standard**，沒有掃過 fast／accurate 的差異。

## 八、重現方式

需要 AEDT 2026.1 與 Q2D Extractor 授權，以及本專案後端環境。

```powershell
# 1. 建立走線路徑並確認弧長↔座標對應
web_app\backend\.venv\Scripts\python.exe validation\cross_section\tdr_profile.py

# 2. 由 s4p 算 TDR Z(距離)
web_app\backend\.venv\Scripts\python.exe validation\cross_section\tdr_curve.py

# 3. 沿線六條截面求解（約兩分半）
web_app\backend\.venv\Scripts\python.exe validation\cross_section\sweep_xs.py

# 4. 追 x=155 的離群值（不需要 AEDT，只讀 EDB）
web_app\backend\.venv\Scripts\python.exe validation\cross_section\probe155.py
```

腳本重用產品的 `app.cross_section` 與 `app.cross_section_q2d`，不是另寫一份演算法——重寫的版本會驗證到一個沒有出貨的東西。

## 九、過程中修掉的三個缺陷

比對本身以外，實跑翻出三個問題，都已修進產品或腳本：

1. **判定「這個點在不在銅箔裡」不能呼叫 `polygon.is_inside()`。** 那在 gRPC 後端是一次來回，一條 14 mm 的切線在 2 µm 間距下有 7000 個取樣點——實測整條要 **404 秒**。改成抓一次頂點、之後在本地做射線判定，同一條降到 **0.4 秒**，結果逐字相同。
2. **適配層必須把切線座標平移成以 0 為中心。** 求解核心的模型以 0 為中心，而我們的座標是板上絕對值；不平移的話導體畫在 82.7 mm、填充只從 −7 到 +7 mm，而 Q2D 照樣解得出來，只是答案沒有意義。
3. **SIwave 的 Interpolating 掃頻給的是不等距頻率格點**，而 skrf 的步階響應要求等距，會直接 `NotImplementedError`——而那個訊息看不出真正的原因是掃頻設定。腳本先重取樣到 4096 個等距點（Δf 12.21 MHz）。
