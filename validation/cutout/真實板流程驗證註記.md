# 真實板上的裁切→建 Port→求解流程驗證

> 補充註記。主驗證見[通道裁切等效性驗證報告](通道裁切等效性驗證報告.md)——
> 那份用自建試片量化「裁切前後的 S 參數差多少」；本註記則是在**真實板**上
> 驗證整條流程跑不跑得起來、要多久。

## 一句話結論

**這份不是量精度的，是量「在一片真的板子上，整條流程跑不跑得起來、要多久」。**

精度那一份是[通道裁切等效性驗證報告](通道裁切等效性驗證報告.md)，
它用自建試片量「裁切前後的 S 參數差多少」。

**兩份要一起看**：一份證明方法正確，一份證明方法在真實規模上做得完。

## 對象

`Example_SYZ.aedb`（本 Repository 內附的範例板）：

| 項目 | 規模 |
|---|---|
| 板面 | 254 × 181 mm |
| 疊構 | 8 個訊號層（SURFACE、L2–L7、BASE） |
| 網路 | 308 條 |
| 走線 | 2663 條 |
| Padstack 實例 | 1941 個 |
| 元件 | 147 個 |

選定通道 `SC_COMPLETE`（長度約 214 mm，走 L5 內層，兩端為 U22、U33）。

## 結果（2026-08-12 實測）

全程使用工具本身的生產程式碼（`app.cutout.run_cutout`、
`app.cutout.create_component_ports`），未做任何客製調整。

| 步驟 | 結果 | 耗時 |
|---|---|---|
| 裁切（ConvexHull、擴張 3 mm、參考 GND） | 162 圖元、64 Padstack、21 元件 | 數秒 |
| 外框比對 | 最大差異 **0.000 mm**、與凸包一致，未降級為 Bounding | — |
| 自動建 Port | 正確判定 U22／U33 為 SMD 接腳，改用 pin-to-layer 電路埠（參考 L2:GND） | 數秒 |
| SIwave SYZ 求解 | 2 埠、501 點、0.01–10 GHz | **34.9 秒** |

## 值得記錄的三點

1. **裁切沒有掉訊號、也沒有靜默降級。** 大型板的已知風險是外框計算失敗後
   悄悄回退成 Bounding（多包大量無關幾何），或 legacy 路徑把訊號網路整批丟掉。
   這次外框比對顯示與凸包完全一致。

2. **Port 型態自動判定正確。** U22／U33 是 SMD 接腳，coax port 在這種焊墊上
   「建得出來」但參考為空、會導致 S 參數全反射。工具正確偵測並改用
   pin-to-layer 電路埠。

3. **35 秒的迴圈讓互動式試誤成為可能。** 這個數字決定了很多功能的可行性——
   任何「改一下再看結果」的流程，只要控制在 SIwave 可信的範圍內
   （見 [SIwave 適用性地圖](../solver_map/SIwave適用性地圖.md)：平面內的走線
   全頻可信且快 120 倍），都能做到接近即時的回饋。

## 範圍

單一通道、單一板、SIwave SYZ、0–10 GHz。這是**流程可行性與耗時**的驗證，
不是精度驗證——裁切的精度量化請看主報告。
