# 真實板上的分段串接對照：微帶線、兩刀、全頻

> **2026-08-18 修正了本報告的因果歸屬。** 初版把偏差的根因寫成「切面缺少接地
> 縫合」。隔天的[微帶線縫合密度驗證](../stitch_density_microstrip/微帶線縫合密度驗證報告.md)
> 把縫合密度從半徑內 14 顆掃到 0 顆，串接誤差散布只有 **0.001 dB**——
> **縫合不是微帶線的變因。** 量到的偏差是真的，但「缺縫合造成的」是當時的推論，
> 不是量測結果。下面已改成量得出來的說法；被推翻的段落保留並標明，
> 不刪掉，因為推翻自己的過程本身是證據。

## 一句話結論

**「分段串接差 0.1 dB 以內」那句話的前提，對 stripline 是「切面有接地縫合」，
對微帶線是「刀數要少、頻率要低」。** 這條真實板的微帶線通道切兩刀，
可用頻率上限只有 1.35 GHz。

主驗證（[分段切板方法驗證報告](分段切板方法驗證報告.md)）用的是自建 stripline
試片、切面有縫合、一刀、0～10 GHz。**這份補的是相反的那一格**：真實板、微帶線、
兩刀、0～20 GHz。

兩份不衝突，但**根因不同**：

| | 決定準不準的是什麼 | 補救方式 |
|---|---|---|
| stripline（雙參考） | 切面處的接地縫合 | 改切在有縫合的位置 |
| 微帶線（單參考） | **刀數與目標頻率** | 減少刀數或改整片求解；**補 Via 沒有用** |

順帶找出一個工具缺陷：**這片板的兩刀當時都被判可用，而且沒有任何提示。**

下面是完整數據與方法。

---

## 為什麼做這一份

2026-07-30 修掉「SIwave 分段後訊號短路」之後，驗收只跑了 10～100 MHz。
假諧振與縫合不足都是高頻才現形，所以那次等於只驗了最不可能出事的頻段
（見 `HANDOFF.md` §三之一）。

這份把同一條通道用兩條路各解一次，比較全頻的差異。

## 方法

| 項目 | 設定 |
|---|---|
| 板子 | `Example_SYZ_Cutout_backdrill_ports.aedb`（真實板，已裁切、已背鑽、已建 Port） |
| 訊號 | ST_CTL、ST_ERROR（**微帶線**，單參考，皆在 L3） |
| 參考 | GND |
| 切點 | x = 76.878 mm、133.604 mm（工具自動選；三段 58.34／56.73／57.53 mm，最大／最小 1.03 倍） |
| 求解器 | SIwave SYZ，**兩邊同一個** |
| 掃頻 | 0 Hz～1 Hz 2 點、1 Hz～100 MHz 每十倍頻 20 點、100 MHz～20 GHz 步距 0.05 GHz（串接後 560 點） |
| 核心 | 1（刻意不佔 HPC_PARALLEL，機器上另有 HFSS 在跑） |
| 對照 | A. 三段各自求解後電路串接　B. 不分割整片求解 |

**兩邊用同一個求解器與同一組掃頻**，否則差異會混進求解器本身的落差而無法歸因。

驅動的是產品自己的 API（`/api/segment/analyze`、`/run`、`/api/schedule/start`、
`/api/cascade/run`），不是另外重寫一份演算法。

原始 Touchstone 在 `results/realboard_20260817/`。

## 原因

### 初版寫錯了，先講結論

**初版說「原因是兩個切點都完全沒有接地縫合」。那是推論，隔天被自己的實驗推翻。**

2026-08-18 建了一片微帶線試片，把縫合密度當唯一變因掃過六種
（半徑 3 mm 內 14／6／2／2／2／0 顆），六條偏差曲線在同一頻率上的最大散布
**9.8×10⁻⁴ dB**。**縫合密度對微帶線完全沒有影響。**

原因很直接：微帶線的回流電流全部在它自己那一個參考面裡，
**從來不需要更深層的 GND 平面**，所以跨層縫合 Via 與這條通道無關。

那量到的偏差從哪裡來？同一片試片、參考面完美連續、最密縫合，
切一刀串接回來：

| 頻段 | 試片（1 刀） | 試片（2 刀） | 兩刀 / 一刀 |
|---|---|---|---|
| 0～1 GHz | 0.016 dB | 0.033 dB | 2.07 |
| 5～10 GHz | 0.636 dB | 0.907 dB | 1.43 |
| 10～15 GHz | 1.285 dB | 2.811 dB | 2.19 |
| 15～20 GHz | 2.077 dB | 4.926 dB | 2.37 |

**切開單參考走線本身就有代價，隨頻率上升、隨刀數累加。** 這條真實板通道切了
兩刀，量到 1.5～2.7 dB，落在試片同條件的量級內——**不需要任何缺陷來解釋它**。

完整數據見[微帶線縫合密度驗證報告](../stitch_density_microstrip/微帶線縫合密度驗證報告.md)。

### 以下是初版的縫合統計（數字正確，因果解讀已作廢）

**保留這一節不是因為它還成立，是因為它是被推翻的那一步。** 幾何統計本身沒有錯，
錯的是把它當成原因。

用工具自己的 `collect_reference_stitch_vias` 與 `evaluate_stitch_coverage` 讀幾何：

| 切點 | 訊號交點（皆 L3、cos = 1.000） | 半徑 3 mm 內縫合 Via | 最近一顆 |
|---|---|---:|---:|
| x = 76.878 mm | ST_CTL y = 82.804、ST_ERROR y = 83.820 | **0 顆** | 6.32 mm |
| x = 133.604 mm | ST_CTL y = 82.169、ST_ERROR y = 84.074 | **0 顆** | 8.05 mm |

整片板總共只有 15 顆參考網路跨層 Via；規則算出這兩處各需要 80 顆。
疊構平均 Dk = 4.4。

工具的判定字面上就是：

> 切面 3.0 mm 內沒有任何參考網路縫合 Via，上下參考平面在此未短路，
> 串接結果不可信。可信上限 0.0 GHz。

規則對這兩刀判不合格，實測的可用上限是 1.35 GHz。**方向一致，但那是巧合**：
規則看的是縫合，而縫合已證實不是微帶線的原因。判對了，理由是錯的。

## 這份找出來的工具缺陷

**那兩刀在分析階段都被判 `valid: True`，而且沒有任何提示。**

原因是舊版把縫合檢查**整個豁免給單參考（微帶線）切面**——所以微帶線切面
不管怎麼切都不會有任何話說。缺陷是「什麼都不講」，這一點無論原因是什麼都要修。

2026-08-17 改成兩種切面都出話，但嚴重度不同：

| 切面 | 缺縫合的判定 | 為什麼 |
|---|---|---|
| 雙參考（stripline） | **D 級**（硬性） | 人為連通兩個原本不相連的平面，生出整片求解沒有的假諧振，實測 12～20 dB |
| 單參考（微帶線） | **風險提示**，不動評級 | 量級小一個數量級，屬「你該知道」不是「這刀不能用」 |

**微帶線那一格的提示文字在 2026-08-18 改過**：初版說機制是回流路徑需要縫合，
並建議「改切在有接地 Via 的位置」。試片證明那個建議**沒有任何用**，
現在改成「減少刀數或改整片求解，補接地 Via 沒有幫助」。

還有一件更根本的事已經記入 `HANDOFF.md`：**這個提示的觸發條件本身（縫合顆數）
與誤差無關**，所以縫合密集的微帶線切面不會出提示，卻有一模一樣的誤差。
該把觸發條件換成「單參考切面＋目標頻率」，跟縫合脫鉤。那會改變提示出現的時機，
屬於行為變更，另案處理。

## 限制

- **只有一片板、一種切點配置。** 這一次量到 1.5～2.7 dB，不足以寫成通則。
- **試片在 15 GHz 以上不合格。** 用來解釋本報告的那片微帶線試片，
  20 GHz 的回波損耗只有 −7.44 dB，所以「兩刀 4.93 dB」這類高頻數字只能當
  趨勢看。合格頻段（≤10 GHz）內真實板仍比試片差 2～3 倍，
  **代表真實板另有因素，只是可以確定那不是縫合顆數。**
- **這片板已套用背鑽**，與 2026-07-30 那次的幾何不同，所以這份**不是重現那次的
  低頻數字**，是在目前這條管線上重做一次全頻對照。
- 兩邊都用 SIwave。HFSS 的量級可能不同——縫合密度驗證就觀察到同一個切面
  SIwave 偏差 21.9 dB、HFSS 只有 2.1 dB。
- 未做重複性統計。

## 一併記下的兩個過程教訓

**掃頻分佈名稱打錯會靜默掃五百萬點。** 第一次跑時把 `"Log Scale"` 打成
`"LogScale"`（少一個空格），工具靜默退回線性步階，「每十倍頻 20 點」變成
「步距 20 Hz」，1 Hz～100 MHz 掃出 5,000,000 個頻點。跑了兩小時、寫出 32.5 GB，
全程沒有警告。已修：擋不認識的名稱，並加上單段 200,000 點的上限。

**伺服器用 `uv run` 起著時，不要在同一個專案目錄再跑 `uv run`。** 第一次求解
跑到一半整棵程序樹消失，就是因為我在後端目錄跑了 `uv run pytest`，
把伺服器正在用的臨時環境重建掉了。改用固定的 `.venv` 起伺服器就不會。
