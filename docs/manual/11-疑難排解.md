# 疑難排解與使用限制

[回操作說明索引](../../操作說明.md)

**這一章是查的，不是讀的**——卡住了用 Ctrl+F 搜錯誤訊息的關鍵字。
後半的「使用限制」開專案前掃一眼。

## 介面檢視操作

Layout 區左鍵拖曳平移、滾輪縮放、右下「Fit All」還原。
圖層面板點欄標頭整欄一起切換。S 參數圖連按兩下開關游標讀值。

## 常見問題

| 症狀 | 原因與處理 |
|---|---|
| **8020 埠被占用** | 多數不用處理，工具自動往上找（最多 21 個）並寫明改用哪個。連續 21 個都被占用，或你用 `-ListenPort` 明確指定時才會報錯。查誰占用：`Get-NetTCPConnection -State Listen -LocalPort 8020`。**確認 PID 用途前不要直接終止**——那可能是別的專案的服務或正在求解的 AEDT |
| **後端 60 秒內沒就緒** | 看後端視窗的**第一個**錯誤（後面多是連鎖反應）。常見：AEDT 2026.1 不可用、Python 版本不支援、套件下載失敗、EDB／AEDT 殘留程序占資源 |
| **按鈕呈灰色** | 「建立 Port 並套用求解器設定」下方會直接列出「還不能建立：…」，從那行排查最快（最常見是「請先執行裁切」）。**輸出路徑不是啟用條件**——沒填按鈕照樣亮，按下去才提示 |
| **大型板裁切很久** | 不要只看瀏覽器有沒有更新就判斷當機。看**載入遮罩的階段、處理數量與系統日誌**——數分鐘到數十分鐘都可能 |
| **裁切包進太多無關銅箔** | 「框選範圍形狀」多半是凸包。**改選貼合走線即可，擴張距離不用動** |
| **選了貼合走線卻變成凸包** | 預檢發現貼合外框沒包住全部訊號幾何（各段擴張後沒連成一片）。**把擴張距離加大**直到各段連起來；日誌會列出落在外框外的頂點座標 |
| **切割位置不合法** | 先分清楚是**硬性阻擋**（切面穿過訊號銅箔，按鈕直接灰掉，只能降 N 或改門檻）還是**軟警告**（交點、角度、淨空——按鈕亮但會跳確認框，**不要直接忽略**） |
| **找不到足夠的合法切面** | 看「遭否決候選」與原因。多半是分段數對這條通道太多（先減少 `N`），或該段本來就佈滿 Via。**F 級不會因為放寬角度而變成可用** |
| **Port 數異常／Design Validation 失敗** | 停止排程，檢查各段 Layout 與 `segments.json`。舊版工具產生的 `segments.json` **排程會拒絕求解**，請用目前版本重新分段 |
| **串接失敗，訊息提到索引型別** | 真正原因是**串接後沒有剩下任何外部 Port**——通道頭尾沒有元件端 Port。用第 03 章補建即可，**不必重跑裁切**（目前版本會在串接前就擋下並說明） |
| **HFSS 高頻反射異常大** | 先確認自適應方式。**同時看耗損**：耗損與 SIwave 接近、只有反射差很多＝**網格問題**，改用「寬頻（Ansys BKM 建議）」重跑；連耗損也對不上才往材料、疊構、Port 定義查 |
| **背鑽殘樁明顯太長** | 檢查該 Via 的「連接層」有沒有漏掉實際有走線或焊墊的層（通道沒包含元件時 BGA 焊墊不存在）。**連接層明顯不對時不要直接寫入——鑽過頭會把訊號切斷，而且要到求解後才發現** |
| **AEDT 設過背鑽卻顯示未設定** | 確認背鑽設在預期的那一側，以及**你開的是不是已寫入背鑽的那份 `.aedb`**（背鑽是另存新檔） |
| **疊構更換後走線或參考平面消失** | 新疊構刪掉了原本存在的層。用原始 EDB 重新開始並修改疊構檔保留該層 |
| **結果接近全反射** | 依序查：Port 是否在正確的訊號 Pin、BGA Port 的 Reference 與負端落點、Stripline 上下參考 Port 有沒有短路、切面 Port 是否垂直且沒切到 Via、切面附近參考平面是否完整、Touchstone Port 順序與接線 |
| **日誌出現「訊號短路」中止該段** | SIwave 網表把兩條訊號併進同一導通區塊，日誌會列出可疑的長距離元件。**這時 S 參數必然不可信，先解決再求解** |
| **眼圖完全閉合** | 把資料速率降到 1～2 Gbps 再跑一次。低速率下張開＝設定正確，閉合是通道在該速率的真實表現。判準：**Nyquist 處衰減超過約 10 dB，無等化下大多無法開眼** |
| **眼高眼寬顯示「眼圖閉合，無法量測」** | AEDT 算不出時回傳 NaN，工具如實標示而不填 0，**避免誤讀成「有量到但為零」**。處理同上 |
| **某段結果被標示為過期** | 分段檔案或設定在求解後有變動。**重新求解該段，不要直接沿用舊 Touchstone 串接** |

### HFSS 段跑很久都沒訊息，是不是當掉了

**多半沒有。** 看包根目錄的 `segment_N_hfss.log`（不是 `logs\` 底下那份），
最後一句是 `Mesh pre-processing took: ...` 就是正在產生網格。**HFSS 3D Layout
的初始網格幾乎是單執行緒**，log 不增長、只吃一顆核心、記憶體持續攀升是正常的。
確認它活著：工作管理員看 `G3dMesher.exe` 的 CPU 時間有沒有累加。

### 眼圖／IBIS 一直停在「正在執行」

先看系統日誌有沒有**「已等待 N 分鐘，求解引擎尚未啟動」**。工具分得出「求解很慢」
與「求解根本沒開始」——慢的求解仍有引擎在跑，授權要不到時是連引擎都沒出現。

到 `%TEMP%\.ansys\` 看 `licdebug.*.out`，求解成功時會有這一行：

```
CHECKOUT elec_solve_level1   NEXXIM.EXE      ← 求解授權拿到了
```

沒有任何 `elec_solve_*` 就是求解授權沒拿到。常見原因：**席次被佔滿**（強制結束的
AEDT 會留下未歸還的簽出）、**授權伺服器不可達**（Licensing Interconnect 與 FlexNet
兩個埠都要通，只通一個會「能開介面、不能求解」）。

> **工具不會自動放棄**——自動中止曾誤殺即將完成的工作。是否停止由你決定。

### 求解機沒有拿到指定的核心數

**核心數不寫在 AEDT 訊息裡，要從授權判斷。** HFSS 內含 4 核，超出的每一核吃一張
`anshpc`（12 核→8 張），用 Ansys License Management Center 看最準。**授權池不夠時
AEDT 會默默降級**，求解包偵測到會寫出可用核心數與建議值。

### 合併分段後 SIwave 報「EnsComEngine returned an error code」

**不要用 AEDT「跨專案複製 design」把分段 EDB 併進同一個專案求解。** 實測複製會弄斷
元件與 pin 的歸屬，元件與 Port 都還在、**但每個元件都變成零腳殼**（39 個元件全數
中招），SIwave 讀到就崩潰。求解請用本工具的排程直接解各分段 EDB，合併檢視用
「串接電路」分頁。目前版本會自動清除零腳 RLC 殼，零腳 IC 殼則擋下並說明。

## 使用限制與建議

- 目前以 Windows 與 **AEDT 2026.1** 為目標環境；處理都在本機，套件安裝階段需要網路。
- 排程**依序求解**，不同時啟動多個 HFSS，以控制授權與記憶體。
- **混合求解的建議只看訊號路徑的三維效應，是工程判斷輔助、不是驗證結論。**
  覆寫不會被阻擋，誤差由使用者評估。
- **背鑽的共振頻率與 Dk 是指示值（約 ±10%），不作為規格依據。**
  寫入前務必確認連接層正確。
- **Layout 清理不能取代工程驗證**——正式專案應比較清理前後的 S 參數。
- 分段串接的準確性取決於 Port 定義、參考結構、切面品質與各段頻率資料的一致性。
- **暫態眼圖是流程驗證，不是統計驗證**：到不了 BER 1e-16，遮罩「通過」只是必要條件。
- **所有眼圖結果都是理想電源**（未經板子的 PDN、不含同時切換雜訊），**裕度是樂觀值**。
- 執行裁切、疊構更換、背鑽、清理與分段前建議備份原始 EDB，所有輸出使用新路徑。
- **請勿將客戶 EDB、AEDT 專案、授權資訊或含機密路徑的日誌提交至公開 Repository。**
