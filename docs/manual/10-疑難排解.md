## 介面檢視操作

- Layout 區左鍵拖曳：平移。
- 滑鼠滾輪：縮放。
- 「Fit All」：重新縮放至全部 Layout。
- 右側箭頭：展開／收合 Layer 面板。
- Layer、Components、Nets 頁籤：控制顯示項目。
- 「完整 Layout」：原始輸入板。
- 「裁切後 Layout」：裁切、補建 Port、疊構更換、背鑽或清理後目前的工作檔。
- 「清理對比」：清理前後及差異高亮。
- 「N 段分割」：整體切割位置或各段 Layout；可切換「安全邊界」與「求解區域」輔助圖層。
- 「串接電路」：分段及 Port 接線示意。
- 「S 參數」：串接後通道的 IL／RL／NEXT／FEXT，可切換單端與差動。
- 「眼圖」：QuickEye 眼圖與眼高、眼寬。
- 底部系統日誌：顯示 PyEDB、Port、Setup、疊構、背鑽、分段、排程、串接與眼圖訊息，可複製或清除。

## 常見問題

### 啟動時顯示 8020 埠已被占用

先查出實際占用程序：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 8020 |
  Select-Object LocalPort, OwningProcess
```

確認 PID 確實是先前啟動的本工具後，再停止：

```powershell
Stop-Process -Id <PID>
```

不要在未確認程序用途前直接終止 PID。

### 後端在 60 秒內沒有就緒

檢查後端 PowerShell 視窗中的第一個錯誤，常見原因包括：

- AEDT 2026.1 或 Ansys Python API 不可用。
- Python 版本不支援。
- 套件下載失敗。
- EDB RPC／AEDT 殘留程序占用資源。
- 8020 埠已被其他程序使用。

### 按鈕呈灰色

| 按鈕 | 啟用條件 |
|---|---|
| 執行裁切（並建立 Port） | 已選擇至少一個訊號 Net 及一個參考 Net。 |
| 建立 Port 與求解器設定 | 已載入 EDB、已選訊號與參考 Net，且已勾選端點元件。 |
| 套用疊構並另存 | 已完成疊構差異分析，且指定新的輸出路徑；會刪層時需先確認。 |
| 寫入背鑽並另存 | 已完成殘樁分析、至少勾選一顆 Via，且指定新的輸出路徑。 |
| Layout 清理 | 已完成裁切，或直接載入既有通道。 |
| 執行清理 | 已完成清理候選分析、候選數大於 0，且指定新的輸出路徑。 |
| 執行 N 段分割 | 已完成切割位置分析。 |
| 開始排程模擬 | 已有有效的 `segments.json`，且目前沒有排程執行中。 |
| 執行電路串接 | 本工具模式需所有分段已有 Touchstone；外部模式需至少一組接線。 |
| 輸出 Circuit／QuickEye | 需先完成串接；QuickEye 只接受 2-Port／4-Port 結果，且需確認眼圖設定。 |

### 大型板裁切或 Port 建立很久

大型 EDB 需要讀取大量 Primitive、Padstack、元件及 Stackup。外框預檢、正式裁切、重新開啟 EDB、Reference 搜尋與預覽擷取都可能需要數分鐘至數十分鐘。請觀察載入遮罩的階段、進度、處理數量及系統日誌，不要只依瀏覽器是否更新判斷當機。

### 裁切範圍包進太多無關的 Via 與銅箔

先確認「框選範圍形狀」是不是**凸包（ConvexHull）**。凸包對斜向或彎折通道一定會多包一塊——內側被一條直線弦切過，弦與走線之間的空白全部進來。改選**貼合走線（Conforming）**即可，擴張距離不用動。

### 選了貼合走線，實際卻變成凸包

代表預檢發現貼合外框沒有包住全部訊號幾何。原因是通道各段在擴張後仍未連成一片，PyEDB 的聯集只回傳了面積最大的那一塊。做法：把「向外擴張距離」加大，直到各段連起來；日誌會列出落在外框之外的頂點座標範圍，可據此判斷是哪一段脫節。

也要確認選取的訊號 Net 是否包含了與主通道完全分離的網路——那種情況本來就不該用同一個裁切範圍。

### 選擇某個外框形狀，結果卻是別的

查看系統日誌中的：

- 要求外框。
- 預檢結果（含貼合外框的訊號覆蓋檢查）。
- 實際外框。
- 回退原因。

回退順序是貼合→凸包→矩形，只有預檢明確失敗或外框無效時才會發生；介面會顯示「上次實際裁切形狀」。

### 分段分析顯示切割位置不合法

不合法通常代表切面靠近 Via／Padstack，未完整穿過走線束，或切面與走線角度不佳。不要直接忽略警告執行；建議調整分段數、清理 Layout 或重新選取真正的通道訊號 Net 後再分析。

### 排程顯示 Port 數量異常或 Design Validation 失敗

先停止排程，檢查各段 Layout 及 `segments.json`。新版流程會在分段輸出前檢查：

- 每一條切面訊號是否都有 Port。
- 每個 Port 是否有 Reference。
- 繼承 Port 與切面 Port 數量是否一致。
- 訊號幾何是否位於正確分段。

若 `segments.json` 是舊版工具產生，排程會拒絕求解；請使用目前版本重新執行 N 段分割。

### 電路串接失敗，訊息提到索引型別

完整訊息是 `arrays used as indices must be of integer (or boolean) type`，來自 scikit-rf 內部。真正的原因是**串接後的網路沒有剩下任何外部 Port**——通道頭尾沒有元件端 Port，所有 Port 都被內部對接掉了。

常見情境是這份 EDB 沒有經過裁切流程，或是載入既有通道後沒有建立元件端 Port。用〈**設定 Port 與求解器**〉補建元件端 Port 後再分段與串接即可，不必重跑裁切。目前版本會在串接前就擋下並說明原因，不會等到 scikit-rf 拋錯。

### HFSS 求解結果在高頻反射異常大

先確認**自適應方式**。若使用單一頻率自適應而該頻率低於掃頻上限，高頻網格會相對過粗而產生數值反射，看起來像嚴重的阻抗不連續。

判別方法是**同時看耗損**：若 HFSS 與 SIwave 的耗損接近、只有反射差很多，那就是網格問題而非物理現象（見「設定求解條件」 的實測表）。改用**寬頻（Ansys BKM 建議）**模式重跑即可。

反之，若連耗損也對不上，才要往材料、疊構或 Port 定義的方向查。

### 背鑽分析算出的殘樁明顯太長

檢查該顆 Via 的「連接層」欄位是否漏掉了實際有走線或焊墊的層。若通道尚未包含元件（例如只匯入了裁切後的走線段），BGA 焊墊不存在，工具就無從得知訊號由該層進入。

此時請確認來源 EDB 含有元件，或手動取消勾選該顆 Via。**不要在連接層明顯不對的情況下直接寫入背鑽**——鑽過頭會把訊號切斷，而且 EDB 上看不出來，要到求解後才會發現通道不通。

### 檢查手動設定的背鑽時顯示「未設定」

用 `get_backdrill_type()` 不帶參數會預設查底面；`get_back_drill_by_layer(from_bottom=False)` 對只設了底面背鑽的 Via 會回傳空層名。用這兩個 API 驗證會出現**假陰性**，把已經設好的 Via 報成未設定。

正確做法是 `core.get_back_drill_type(side)` 搭配 `get_back_drill_by_depth(side)`，兩側都查。

### 疊構更換後走線或參考平面消失

新疊構刪掉了原本存在的層。差異分析會把「移除」的層列出並要求確認（`requires_confirmation`）；若已經套用，請用原始 EDB 重新開始，並修改疊構檔保留該層。

### 模擬結果接近全反射

優先檢查：

1. 元件端 Port 是否位於正確訊號 Pin。
2. Solder Ball／BGA Port 是否有正確 Reference，且負端落在參考 Via 中心（見「設定元件端 Port」）。
3. Stripline 是否建立上下兩個參考 Port，且串接時被短路成同一節點。
4. 切面 Port 是否垂直於走線、沒有切到 Via／Pad。
5. 每段的參考平面在切面附近是否完整。
6. Touchstone Port 順序、命名及接線是否正確。

若排程日誌出現「訊號短路」而中止該段，代表 SIwave 網表把兩條訊號併進同一導通區塊，日誌會列出可疑的長距離元件；此時 S 參數必然不可信，應先解決該問題再求解。

### 分析後找不到足夠的合法切面

先看分析結果列出的「遭否決候選」與原因。常見情況：

- 分段數對這條通道太多，切面被擠在障礙物附近；先減少 `N` 再試。
- 通道某段本來就佈滿 Via 或銅箔，該處無法切；此時減少分段數比放寬門檻合理。
- 硬性阻擋（F 級，切面穿過訊號銅箔）不會被採用，放寬角度容差也不會讓它變成可用。

### 混合求解該怎麼分配

先按「套用自動建議」，再逐段複核。工具建議 HFSS 的段，是因為**訊號路徑本身**有換層過孔、訊號 Via 或元件端 launch；把這類段改成 SIwave 雖然快，但這些真三維結構會被平面波近似低估，介面會顯示警示（但不阻擋）。

反過來，若某段被建議 SIwave 而你直覺覺得「這片板這麼多層、Via 這麼密，怎麼可能用 SIwave」，請看「判斷原因」欄。板子總層數與 GND 縫合 Via 密度**刻意不列入評分**——它們不在訊號路徑上，SIwave 處理得很好。像「訊號在段內單層直通、屬地勻傳輸線結構」這種段，用 SIwave 就足夠，把求解時間留給真正需要 HFSS 的段。

若某段結果被標示為過期，代表分段檔案或設定在求解後有變動，需重新求解該段，不要直接沿用舊 Touchstone 串接。

### 遠端求解包的 HFSS 段跑很久都沒訊息，是不是當掉了

**多半沒有。** 先看包根目錄的 `segment_N_hfss.log`（不是 `logs\` 底下那份），
如果最後一句是 `Mesh pre-processing took: ...`，代表它正在產生網格。

HFSS 3D Layout 的初始網格幾乎是單執行緒的，實測有效核心數約 1。這段期間 log
不增長、CPU 只吃一顆、記憶體卻持續攀升——大型分段停在這裡數十分鐘很正常。

想確認它真的活著，用工作管理員看 `ansysedt.exe` 底下有沒有 `ENSCOMENGINE.exe`
與 `G3dMesher.exe`，並觀察 `G3dMesher` 的 CPU 時間是不是還在累加。有在累加就是
在跑，核心數要進到矩陣求解才會展開。

### 求解機沒有拿到指定的核心數

核心數不會寫在 AEDT 訊息裡，要從授權判斷：HFSS 求解內含 4 核，超出的每一核吃一張
`anshpc`，所以 12 核佔 8 張、36 核佔 32 張。用 Ansys License Management Center 看
`anshpc` 的用量最準。

若授權池不夠，AEDT 會默默降級成拿得到的核心數。求解包偵測到時會寫出「這台機器
只有 N 核可用，但要求了 M 核」與建議值——請把求解核心數改成該值（或更小）後重新
打包。

反過來說，**多台機器共用同一組授權伺服器時要留意互搶**：另一台在跑的求解會把
`anshpc` 佔走，這一台就只能拿到剩下的。

### 合併分段後 SIwave 報「EnsComEngine returned an error code」

**不要把分段 EDB 用 AEDT「跨專案複製 design」合併進同一個專案再求解。**
實測：複製會弄斷元件與 pin 的歸屬——元件物件與 Port 都還在，但每個元件都
變成零腳殼（39 個元件全數中招）。SIwave 求解器讀電路元件時遇到零腳殼會以
signal 11 崩潰，AEDT 只回報一句沒有資訊量的
「EnsComEngine returned an error code. Please contact Ansys technical support.」

正確做法：

- **求解**用本工具的排程，直接解各分段 EDB——工具切出來的分段元件腳位完好，
  不需要合併就能逐段求解。
- **合併檢視**用「串接電路」分頁的示意圖，不必為了看全貌把 EDB 併起來。

工具的排程與不分割流程現在會在求解前檢查：零腳的 RLC 元件殼自動清除；
零腳的 IC 殼（刪除會連帶刪掉其上的元件端 Port）則明確擋下並說明處理方式，
不會讓它進到求解器領一句通用錯誤。

### 眼圖完全閉合

先確認這是不是通道本身的物理結果，而不是設定問題：把資料速率降到 1～2 Gbps 再跑一次。若低速率下眼圖張開，表示設定正確，閉合是通道在該速率下的真實表現。

判斷可用速率的依據是通道的插入損耗：Nyquist 頻率（資料速率的一半）處若已衰減超過約 10 dB，無等化下大多無法開眼。

### 眼高、眼寬顯示「眼圖閉合，無法量測」

眼圖完全閉合時 AEDT 算不出眼高與眼寬，回傳 NaN。工具如實標示而不填 0，避免誤讀成「有量到但為零」。處理方式同上一項。

## 使用限制與建議

- 本工具目前以 Windows 與 AEDT 2026.1 為目標環境。
- EDB、AEDT 與 Touchstone 處理皆在本機進行；套件安裝階段需要網路。
- 排程採依序求解，不會同時啟動多個 HFSS 3D Layout 求解，以控制授權及記憶體需求。
- 混合求解的建議只看訊號路徑的三維效應，屬工程判斷輔助，不是驗證結論；覆寫建議不會被阻擋，誤差由使用者評估。
- 背鑽的共振頻率與介電常數為指示值（Dk 約 ±10%），不作為規格依據；寫入前務必確認「連接層」判斷正確，鑽過頭會把訊號切斷。
- 疊構更換若刪去現有層，該層上的走線與參考平面會一併消失；套用前務必看過差異分析。
- Layout 清理屬於幾何／電磁影響範圍判斷，不能取代工程驗證。正式專案應比較清理前後的 S 參數，確認誤差符合需求。
- 分段串接的準確性取決於 Port 定義、參考結構、切面品質及各段頻率資料的一致性。
- QuickEye 是流程快速驗證，不取代完整 Tx／Rx、IBIS／AMI、抖動與遮罩驗證。
- 執行裁切、疊構更換、背鑽、清理與分段前，建議備份原始 EDB；所有輸出請使用新路徑。
- 請勿將客戶 EDB、AEDT 專案、授權資訊或含機密路徑的日誌提交至公開 GitHub Repository。
