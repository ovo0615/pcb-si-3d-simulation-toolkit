## 加速手法必須先證明不犧牲精度

本工具的加速做法（只取通道、分段求解、逐段挑求解器）都會改動求解對象本身，因此每一項都必須回答同一個問題：**這樣做出來的結果，跟老老實實整片解一次差多少？** 目前已完成量化驗證的四項，原始數據與失敗案例全部公開：

| 驗證項目 | 對照基準 | 結果 |
|---|---|---|
| [通道裁切](validation/cutout/README.md) | 同一片試片不裁切、直接求解 | 插入損耗偏差 **0.03 dB 以內**（擴張 2～5 mm） |
| [Layout 清理](validation/cleanup/README.md) | 同一片試片不清理、干擾物全部保留 | 插入損耗偏差 **0.021 dB 以內**（四種保護距離） |
| [分段切割 + 電路串接](validation/segmentation/README.md) | 同一片試片不切割、單體全波求解 | 插入損耗偏差 **0.1 dB 以內（0～10 GHz）**，前提是切面有縫合 |
| [TDR 群延遲定位](validation/tdr/README.md) | 建模時已知的幾何邊界位置 | 平均定位誤差 **0.66 mm**、最大 **1.71 mm** |

三份驗證都刻意包含**負控制組**——會失敗的情形長什麼樣子。裁切與分段兩項驗證**各自獨立地指向同一個根因**：決定準確度的是參考平面的接地縫合狀況，而不是擴張距離或切面角度。缺少縫合時，分段會產生 14 dB 的假諧振、裁切會產生 1.6 dB 的偏差；這個條件已成為工具的自動檢查並擋在使用者前面。

**表格裡的數字都來自自建試片，而且切面有縫合。那個前提不是小字，是主詞。**
真實板上切在 3 mm 內完全沒有縫合 Via 的位置時，分段串接的**可用頻率上限只剩
1.35 GHz**——低頻仍然很準（0～1 GHz 差 0.040 dB），但 3 GHz 以上就長到 1.5 dB
以上。見[真實板全頻對照](validation/segmentation/真實板全頻對照_20260817.md)。

驗證的價值不在背書，在於找出方法的邊界，然後把邊界寫進工具裡。

三項會改動求解對象的加速手法（裁切、清理、分段）現在都有量化數據。

驗證也用來檢討工具自己：[四項求解器與分段研究](validation/分段與求解器研究總覽.md)找出了自適應預設值少算 3.2 dB、切面檢查放行 21.9 dB 誤差、彎折被誤當成複雜度三個問題，均已修正。仍未單獨驗證的是「逐段挑求解器」——那是求解器等價性問題，性質與前三項不同，列為後續工作。
